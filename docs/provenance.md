Schema verification also consulted the public floodlight DFL reader: https://floodlight.readthedocs.io/en/latest/_modules/floodlight/io/dfl.html . The adapter is newly implemented using Python's standard library, not a copy of floodlight.

## Official public code

`vendor/official` contains unchanged copies of the competition's publicly released `evaluation/possession_metrics.py`, `starter/baseline.py`, `games.py` and MIT `LICENSE`. No evaluation labels or match data were copied. Origin: https://github.com/metrica-sports/more-than-a-hack-2027 . Hashes are recorded in `vendor/official/source_manifest.json`. No upstream Git SHA is available from the user's ZIP checkout; content hashes identify the exact source instead.

Our smoothing implementation is a small semantic port with explicit per-sequence resets. Synthetic tests compare it to the public official implementation. The metric code is imported unchanged and hashed in every external evaluation report.

## Reproduction and isolation

The runtime versions and adapter source hashes are included in the preparation manifest. Predictions and metrics bind to their input hashes. Repeated runs must produce identical arrays and metric values. No timestamped operational fields are inserted into deterministic artefacts.

Only source, synthetic tests, docs, config, and public official code belong in the distributable checkpoint. External raw assets remain locally acquired from the stated source; restricted competition assets and derived outputs are not accessed by this milestone.
